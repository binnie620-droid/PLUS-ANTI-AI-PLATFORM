# PLUS FUTURE AI ANTI PLATFORM

**한화투자증권 PB팀 · 안티플랫폼 데스크**
주제: AI 고도화 시대, 어떤 종목에 투자할 것인가

---

> ## 시장은 AI를 **호재**라고 부르고, 우리는 AI를 **시험**이라고 부른다.
>
> AI는 모든 상장사에 같은 시험을 치르게 한다. **수요를 얻는 회사**와 **이익을 뺏기는 회사**가
> 갈리는데, 시장은 양쪽에 똑같이 "AI 수혜" 멀티플을 얹는다. 부호가 반대인데도.
> **그 오류가 우리의 수익이다.**

| | |
|---|---|
| **대상** | 코스피 · 코스닥 상장, **애널리스트 컨센서스가 존재하는 기업만** |
| **기준선** | 현재가 + 컨센서스 목표주가 |
| **필수 데이터** | DART · FnGuide 컨센서스 · FRED |
| **인원** | 4명 (개발 1명) |
| **중간제출** | 2026-08-12 23:00 |

## 빠른 시작 — 직접 돌려보기

**Claude Code 플러그인으로 설치한다.** 저장소를 clone할 필요도 없다.

```
/plugin marketplace add binnie620-droid/PLUS-ANTI-AI-PLATFORM
/plugin install dpic-desk@dpic
/dpic-desk:desk-setup
```

`desk-setup` 이 API 키 발급 안내부터 데이터 수집까지 끝내준다. 그다음:

```
/dpic-desk:industry-screen     산업 판정
/dpic-desk:company-screen      종목 전수 판정
/dpic-desk:pro_tackler         태클 심사
/dpic-desk:desk-head           최종 투자보고서
/dpic-desk:desk-run            위 순서를 한 번에
```

### 알아둘 것

- **Python 3.9 이상만 있으면 된다. `pip install` 불필요** — `tools/` 전부 표준 라이브러리만 쓴다
- **필요한 키는 DART와 FRED 둘뿐이다.** 둘 다 무료이고 즉시 발급된다
  ([DART](https://opendart.fss.or.kr) · [FRED](https://fred.stlouisfed.org/docs/api/api_key.html))
- **3단계(조정률 산출)에서 멈추는 것은 정상이다.** 그 계산을 하는 `core/` 는 미구현이라
  `desk-run` 이 수동 입력을 안내하고 정지한다. 버그가 아니다
- 산출물(`data/` · `runs/`)은 **현재 프로젝트 폴더**에 쌓인다. 플러그인 설치 위치는 건드리지 않는다

### 키 없이 결과만 보려면

이미 돌린 기록이 저장소에 그대로 들어 있다.

```
runs/2026-08-13_전력기기·중전기/    01~04 + report.html   전력기기 7개사 전수 심사
runs/2026-08-13_discover/           산업 discover 결과
```

`report.html` 을 브라우저로 열면 된다. 7개사 중 1개만 통과했고, 그마저
팀장 단계에서 **투자보류로 뒤집힌** 기록이다.

### clone해서 쓰려면

```bash
git clone https://github.com/binnie620-droid/PLUS-ANTI-AI-PLATFORM.git
cd PLUS-ANTI-AI-PLATFORM
cp .env.example .env          # DART_API_KEY · FRED_API_KEY 채우기
```

그 폴더에서 Claude Code를 열면 스킬이 프로젝트 스킬로 잡힌다. 이때는
`dpic-desk:` 접두어 없이 `/desk-setup`, `/industry-screen` 으로 부른다.

## 1. 한눈에

```
[관심분야 or 지정산업]
   │
   ├─ Skill 1/1.5  산업 스크린   컨센 보유 종목 5개 이상인가?          [B]
   │                             └ 미달 → REJECT
   ├─ Skill 2      기업 판정     Q1~Q5 예/아니오 + DART 인용           [C]
   │                             └ 인용 없는 YES → NO 강제
   ├─ Core         조정률 산출   조정률 → 우리 TP → 컨센 델타          [A]
   │                             └ |델타| < 20%p → NO CALL
   ├─ Skill 3      태클봇        pro_tackler: F1·F2 → M1 → 인과 → M2~M4  [D]
   │                             └ FAIL 2개 이상 → 폐기
   └─ Skill 4      팀장          하드컷·정렬·분산 → 3종목 + 배분       [D]
                                 └ 최대 기여 질문 중복 → 재구성
```

### 세 개의 진입점, 하나의 게이트

| 진입 | 사용자 | 경로 |
|---|---|---|
| 산업 추천 | "AI 시대에 뭐가 유망해?" | `1 → 2 → Core → 3 → 4` |
| **산업 지정** | "농업으로 뽑아줘" | `1.5 → 2 → Core → 3 → 4` |
| 지정 후 반발 | "네가 그렇게 똑똑해?" | `1.5 결과 제시` (별도 로직 없음) |

**다른 팀 사람은 반드시 "산업 지정" 경로로 들어온다.** 그 경로에도 게이트가 전부 걸려 있어야
완성정의 — *"규칙서와 도구만 받아 우리가 안 본 대상에 판단"* — 를 통과한다.

## 2. 왜 이렇게 설계했나 — 회의에서 안 정해진 것 8개

| # | 허점 | 해법 |
|---|---|---|
| **G1** | 컨센서스 없는 종목이 뽑히면 8/13에 **대조 상대가 없다** | 커버리지를 추천 후 필터가 아니라 **유니버스 정의**로. 산업 통과 조건 = 커버리지 3곳 이상 종목이 5개 이상 |
| **G2** | "그것 또한 AI"는 평가에서 죽는다 (블랙박스) | **AI는 판정만, 계산은 코드가.** AI 출력은 예/아니오와 인용뿐. 인용 없으면 코드가 NO로 강제 |
| **G3** | 유니버스가 큰데 뭘로 5개를 뽑나 | **팀명이 답.** PLUS FUTURE(수요) + ANTI(대체불가)를 5문항으로. 전수 판정 후 정렬 |
| **G4** | "왜 유망한데?" 자유 반박은 잡음 | **고정 3시험만. 기본값 FAIL.** LLM은 동의하는 경향이 있어 명시하지 않으면 다 통과시킨다 |
| **G5** | "돈을 벌어와야 한다"는 측정 불가 | 하드컷 4개 + 기대수익 정렬 + 분산 규칙 |
| **G6** | "대체불가"와 "미래효용"이 같은 말로 붕괴 | **공급측 / 수요측**으로 직교. 이래야 **☠ 함정 영역**이 보인다 |
| **G7** | 개발자 1명인데 전원 커밋 의무 | **스킬은 마크다운 파일.** 판단 기준을 쓰는 건 개발이 아니라 리서치 |
| **G8** | 이게 PB 업무가 맞나 (skill 1~3은 리서치) | 정체성은 PB 유지. **최종 산출물이 리포트가 아니라 포트폴리오 제안서**여야 한다 |

### G8이 오히려 득점 요인인 이유

평가기준 3번은 *"판단대로 투자했을 때 얼마나 벌 수 있는가"* 다.
리서치는 목표주가만 맞히면 되지만 **PB는 금액으로 답해야 한다.**
즉 이 과제의 채점 방식 자체가 리서치보다 PB에 가깝다.

## 3. 판단 규칙

### 3-1. 목표주가를 만들지 않는다

```
폐기   우리 TP = 멀티플 × EPS × G        ← 멀티플을 새로 만들어야 함 (앵커 바스켓 필요)
채택   우리 TP = 컨센 TP × (1 + 조정률)   ← 컨센 TP 하나만 있으면 됨
```

**EPS도 PER도 앵커 바스켓도 필요 없다.** FnGuide에서 받는 `consensus_tp` 하나로 끝나고,
**델타가 곧 조정률**이라 계산이 사라진다.

논리적으로도 이쪽이 정직하다. 우리는 애널리스트보다 재무모델을 잘 만들 수 없다.
우리가 잘할 수 있는 건 **애널리스트가 안 본 것을 반영해서 그 숫자를 밀거나 당기는 것**뿐이다.

### 3-2. 조정 체크리스트 — 5문항 예/아니오

| # | 이름 | 질문 | YES |
|---|---|---|---|
| **Q1** | 이익 대체성 | 영업이익의 50% 이상이 **AI로 대체 가능한 인지노동**에서 나오는가 | **−25%p** |
| **Q2** | 진입 장벽 | 면허·설비·실적 때문에 신규 경쟁자가 **3년 내 진입 불가**한가 | **+10%p** |
| **Q3** | 수요 연동 | AI 확산이 매출을 직접 늘리는 경로가 **공시에 있는가** | **+15%p** |
| **Q4** | 원가 수혜 | AI로 낮출 수 있는 인건비·설계비가 **매출의 10% 이상**인가 | **+5%p** |
| **Q5** | 갱신 지연 | **컨센 최종 갱신일 이후** 중요 공시(수주·실적·제도)가 있었는가 | **+10%p** |

조정률 범위 **−25% ~ +40%**

- 0~3점 채점은 "2점인가 3점인가"로 매번 흔들린다. **예/아니오는 안 흔들린다** → 재현성
- **Q1이 혼자 −25%p로 무거운 게 핵심.** 함정 종목(Q1 YES + Q3 YES = −10%)에서
  **하향 판단이 자동으로 나온다.** 상향만 내는 데스크는 신뢰를 못 받는다.

#### 인용 강제

**모든 YES에는 DART 원문 인용이 붙는다. 없으면 코드가 NO로 강제한다.**

| 가능 | 불가 |
|---|---|
| 사업보고서 "II. 사업의 내용" | 뉴스 기사 |
| 사업보고서 "III. 재무에 관한 사항" | 애널리스트 리포트 |
| 주요사항보고서 · 수시공시 | IR 자료 · 블로그 |

**금지어** — 나오면 그 항목 자동 NO:
`업계 통념상` `일반적으로` `~로 알려져 있다` `~로 판단된다` `~일 것으로 보인다`

### 3-3. 계산

```
조정률   = Σ (YES 항목의 가중치)
우리 TP  = 컨센 TP × (1 + 조정률 × G)      # G는 조정률 > 0 일 때만 적용
델타     = 조정률 × G                       # 평가기준 2 (차별성)
업사이드 = 우리 TP / 현재가 − 1             # 평가기준 3 (수익규모)
승률     = 0.55 − 0.15 × 검증 FAIL수
기대수익 = 업사이드 × 승률
```

**FRED 게이트 G** — 상방에만 적용

| G | 조건 |
|---|---|
| 1.00 | 미 10년 실질금리 하락 또는 횡보 |
| 0.85 | 상승 중 (3개월 +50bp 미만) |
| 0.50 | 급등 (3개월 +50bp 이상) |

금리가 올랐다고 하락 논리를 약화시킬 이유가 없다. 보수적으로 간다.

### 3-4. 검증 3시험 — 각각 C의 특정 YES를 공격

| # | 시험 | 공격 대상 | FAIL 조건 |
|---|---|---|---|
| **V1** | 프론티어랩 진입 | Q2 진입장벽 | 그 장벽이 1년 내 무너질 수 있음 |
| **V2** | 이익 귀속 | Q4 원가수혜 | 절감분이 고객·경쟁으로 전이 |
| **V3** | 이미 반영 | 전체 | 12개월 시장 대비 초과상승 30% 이상 |

```
FAIL 2개 이상 → 폐기      FAIL 1개 → 승률 하향      FAIL 0개 → 통과
```

**기본값은 FAIL.** LLM은 상대에게 동의하는 쪽으로 기울어 있다. 명시하지 않으면
형식적으로 반박하는 척하다 결국 전부 통과시킨다.

**V2가 진짜 무기다.** "AI로 원가가 낮아진다"는 대부분 틀리다. 경쟁자도 같이 낮아지면
절감분은 고객에게 넘어가고 마진은 그대로다. `Q2=NO`인데 `Q4=YES`인 종목은 반드시 FAIL.

### 3-5. 최종 선정 — 채점 없이 정렬과 컷만

```
1단계 · 하드 컷
   컨센 커버리지 3곳 미만       → 제외
   |조정률| < 20%p              → 제외 (컨센과 차이 없으면 수익원이 없음)
   20일 평균 거래대금 기준 미달  → 제외 (고객 자금이 안 들어가면 상품이 아님)
   검증 FAIL 2개 이상           → 제외

2단계 · 정렬
   기대수익 = 업사이드 × 승률    내림차순

3단계 · 분산 규칙
   위에서부터 담되, 이미 담은 종목과
   「조정률의 최대 기여 질문」이 같으면 건너뛴다
```

**3단계가 팀장의 진짜 판단이다.** 셋 다 Q5(갱신 지연)로 저평가된 종목이면
**컨센이 한 번 갱신되는 순간 셋이 동시에 죽는다.** 서로 다른 이유로 저평가된 종목을
모아야 분산이다.

### 3-6. 폐기 게이트 5개

```
1. 컨센 커버리지 3곳 미만          → 제외
2. |조정률| < 20%p                → NO CALL
3. 인용 없는 YES                  → NO로 강제
4. 검증 FAIL 2개 이상              → 폐기
5. 최종 3종목 최대 기여 질문 중복   → 재구성
```

## 4. 데이터 스키마 — 절대 바꾸지 않는다

### `data/consensus.csv`
```csv
ticker,name,consensus_tp,coverage_count,last_updated
```
| 열 | 용도 |
|---|---|
| `ticker` | 6자리 **문자열** (앞자리 0 유지) |
| `consensus_tp` | 컨센 목표주가 — **이것 하나로 밸류에이션 끝** |
| `coverage_count` | 3 미만이면 제외 (G1) |
| `last_updated` | Q5 판정 입력 |

### `data/price.csv`
```csv
ticker,price,turnover_20d,rel_return_12m
```
`rel_return_12m` = 12개월 시장 대비 초과수익률 (V3 판정용)

> FnGuide를 어떤 형식으로 받든 이 열들로 정규화한다. 형식이 바뀌면 **어댑터만** 고치고,
> 최악의 경우 손으로 채워도 파이프라인이 돈다. **열 이름이 안 정해지면 4명 전부가 막힌다.**

## 7. 역할별 주의사항

### A · 개발 (`main`)

> 남이 정한 기준을 정확히 실행하는 층만 맡는다. **판단은 하지 않는다.**

- **★ 인용 검사기를 코드에 넣어라.** 스킬 프롬프트만으로는 절대 지켜지지 않는다.
  ```python
  MIN_EVIDENCE_LEN = 20
  BANNED = ["업계 통념상", "일반적으로", "알려져 있다", "판단된다", "보인다"]

  def has_evidence(evidence, q):
      e = evidence.get(q) or {}
      quote = (e.get("quote") or "").strip()
      if len(quote) < MIN_EVIDENCE_LEN:       return False
      if any(b in quote for b in BANNED):     return False
      if not (e.get("source") or "").strip(): return False
      return True
  ```
- **★ 관통을 최우선.** 종목 1개를 skill 1부터 리포트까지 통과시키는 게 먼저다.
  함수를 예쁘게 만들다가 자정을 넘기는 게 가장 흔한 실패다.
- **`ticker`는 문자열로 읽어라.** `pandas.read_csv`가 `005930`을 `5930`으로 읽는다.
  `dtype={"ticker": str}` 필수 — 이거 하나로 밤에 한 시간 날린다.
- **AI에게 산수를 시키지 마라.** 스킬이 조정률을 계산해줘도 무시하고 예/아니오만 받아 직접 계산.
- **G는 상방에만.** `tp = cons_tp * (1 + rate * (G if rate > 0 else 1.0))`
- **재현성 테스트** — 3회 실행해 조정률이 흔들리면 어느 질문에서 흔들리는지 기록.
  결과를 리포트에 첨부하면 "작동여부" 점수가 확보된다.

**하지 말 것** — 웹 UI · 크롤러 · DB · 테스트 커버리지 · 멀티플/PER/EPS 코드

### B · 산업 (`industry`)

> 산업에 점수를 매기지 않는다. **통과 / 반려만 있다.**

- **★ 커버리지 3~5곳이 스위트스팟이다.**

  | 커버리지 | 판정 | 이유 |
  |---|---|---|
  | 0~2곳 | 탈락 | 대조 불가 |
  | **3~5곳** | **최적** | 대조는 되는데 얇아서 **정보 우위가 존재** |
  | 10곳 이상 | 위험 | 이미 다 알려짐. **V3에서 전멸** |

  **로보틱스·반도체·데이터센터를 추천하면 안 되는 이유가 이것이다.** 회의에서
  "마음에 안 든다"고 한 그 셋이 실제로 우리 기준에서 탈락한다.
  **모두가 보고 있는 산업엔 델타가 없다.**

- **★ "유망한" 산업이 아니라 "조정률이 나올 수 있는" 산업**을 골라라.
  Q1이 명확히 NO인 산업(물질·현장·면허 기반), Q3가 공시로 확인되는 산업,
  Q5가 자주 발생하는 산업(커버리지가 얇아 갱신이 느림).
- **☠ 함정 산업도 후보로 남겨라.** Q1이 YES인 산업 — 컨설팅·SI·번역·인력파견.
  `"expected_direction": "DOWN"`으로 표시해서 넘긴다.
- **discover와 verify는 파일 하나 안의 두 모드.** 나누면 기준이 갈라진다.
- **유니버스는 고정 CSV가 아니라 `data/industry_cache.json`.** discover가 브레인스토밍한
  후보 산업은 `tools/dart_lookup.py`로 실존을 확인하며 캐시에 자동 편입된다 — 사람이 손으로
  채우는 목록이 아니다. 이래야 "설비·물질 기반 중공업"에만 몰리지 않고 서비스·금융 등
  Q1-YES 함정(☠) 후보도 나올 수 있다.
- **출력은 JSON.** 산문으로 설명하면 A가 파싱할 수 없다.

```json
{
  "mode": "verify",
  "industries": [{
    "name": "농업",
    "consensus_universe_count": 7,
    "gate": "PASS",
    "answerable_questions": ["Q1","Q2","Q3","Q5"],
    "expected_direction": "UP",
    "reason": "커버리지 3~5곳 구간, 물질·현장 기반으로 Q1이 명확히 NO"
  }]
}
```

### C · 기업 (`company`)

> 이 데스크의 **차별성이 전부 여기서 만들어진다.** 그리고 가장 망가지기 쉬운 자리다.

- **★ 인용 없으면 NO — 이 규칙을 지키는 게 C의 전부다.**
  A의 코드가 20자 미만이거나 금지어가 있으면 강제로 NO로 덮어쓴다.
- **★ 기본값은 NO다.** YES를 남발하면 모든 종목이 +40%가 되어 변별력이 사라진다.
  각 질문을 NO로 시작해 **인용 가능한 근거가 나올 때만** YES로 올린다.
  에이전트 프롬프트에 "불확실하면 NO"를 명시하라.
- **★ Q1을 빼먹지 마라 — 하향 판단의 유일한 출처다.** 다른 넷은 전부 플러스인데
  Q1만 −25%p다. Q1을 대충 NO로 넘기면 **모든 종목이 상향 판단이 되고 신뢰도가 무너진다.**

  Q1 YES 후보: 매출 절반 이상이 `용역` `컨설팅` `설계` `번역` `콘텐츠 제작` `인력 파견`,
  판관비 중 인건비 비중이 압도적, 수주 단위가 `인월(MM)` 기준
- **★ 상위 종목을 먼저 정하고 답을 맞추지 마라.** 역방향 오염이며, 발생하면
  조정표가 장식이 된다. **전수 판정하고 정렬은 A의 코드가 한다.**
- **NO인 질문은 근거가 필요 없다.** YES에만 인용을 단다.

```json
        "source": "2025 사업보고서 II.사업의 내용 p.14"
```

### D · 반박 및 검증 (`falsify`) — 스킬 `pro_tackler`

> 우리 논리를 죽이는 역할. **자유 반박 금지.**
> 구현체는 `.claude/skills/pro_tackler/SKILL.md`. 아래는 요약이며 **판정 기준의
> 정본은 그 파일이다.**

C가 보낸 기업 보고서 5건을 심사해 **최종 3개**를 골라 팀장에게 넘긴다.

#### ★ 호흡이 10~20년임을 잊지 마라

**12개월 기준으로 재지 마라.** 단기 리서치 규범을 적용하면 좋은 장기 주장이 전부 죽는다.

```
전제 (현재 사실)     확인 가능한데 안 했으면 즉사
연결고리 (논리)      ★ 여기를 턴다
결론 (미래 추론)     불확실성 허용
```

**같은 "가능성이 있다"도 위치에 따라 갈린다.**

```
✕  "이 회사는 면허를 보유한 것으로 보인다"        → 전제. 확인 가능한데 안 함. FAIL
○  "10년 뒤 이 면허 가치가 커질 가능성이 있다"     → 결론. 통과
```

#### 심사 순서

```
Phase 0    인과 사슬 분해      P ──①──▶ M ──②──▶ R 로 명시화
Phase 1    전제 심사 (즉사)    F1 근거 / F2 규모(시점 아닌 크기)
Phase 1.5  M1 AI 잠식 선판정   L1~L5.  L1~L2 + 산업↑ = ☠ 함정
Phase 2    인과 공격 5종  ★    비약 · 필요≠충분 · 역방향 · 제3원인 · 귀속누락
Phase 3    M2 산업성장 / M3 이익귀속 / M4 상투어
Phase 4    선정 — 최대 3개, 미달이면 미달인 채로
```

- **기본값 FAIL** — 단, **전제와 연결고리에만** 적용한다. 결론의 불확실성은 감점하지 않는다.
- **끊긴 고리 2개 이상 → 탈락**, 1개 → 감점 1
- **M1이 L1~L2면 즉사.** 산업이 성장 중이면 `☠ 함정`으로 표기해 **하향 판단 후보**로 넘긴다
- **M3는 DART 동종 3사 영업이익률 추이로 증거화**한다. 3사가 동조하면 이 회사만의 이익이 아니다
- **편입 0개일 때만 반려 지시서를 발행**한다. 평소엔 심사표의 탈락사유 칸으로 끝낸다

#### Q1~Q5와의 관계

C가 쓰는 조정 체크리스트(§3-2)의 **Q1(이익 대체성)을 정밀화한 것이 M1의 L사다리**다.
Q1은 예/아니오 2단계, M1은 5단계다. **판정이 갈리면 M1을 따른다.**

```json
{
  "ticker": "000000",
  "F1": "PASS", "F2": "PASS",
  "M1": {"level": "L4", "score": 3, "basis": "감속기 제조 — 영업이익 85%"},
  "causal_breaks": 1,
  "M2": 2, "M3": 0, "M4": 2,
  "m_total": 7, "penalty": 1, "final": 6,
  "verdict": "편입 2위"
}
```

### 팀장 (`desk-head`)

> **재판정하지 않는다. 규칙 적용자다.** 채점표를 뺐기 때문에 역할이 오히려 정확해졌다.

- **★ 분산 규칙이 진짜 판단이다.** 이미 담은 종목과 「조정률의 최대 기여 질문」이
  같으면 건너뛴다. 최대 기여 질문은 A의 코드가 자동으로 뽑아 준다.
- **★ 배분 비중과 금액 기대수익을 반드시 넣어라.** 이게 G8 —
  **리서치와 PB를 가르는 유일한 지점**이다.

#### 리포트에 반드시 들어갈 4가지

**① 배분 비중**
```
A종목 40% / B종목 35% / C종목 25%
```
PB는 종목이 아니라 **배분**을 판다.

**② 금액 기준 기대수익** — 가장 중요
```
1억 배분 시 기대수익 +1,700만원 (기대수익률 +17.0%)
  A종목 4,000만 × +32.0% × 0.55 = +704만
  B종목 3,500만 × +25.0% × 0.40 = +350만
  C종목 2,500만 × +28.0% × 0.55 = +385만
```
**평가기준 3번이 요구하는 형식이 정확히 이것이다.**

**③ 청산 규칙**
```
매도: pro_tackler 재심사에서 인과 끊김이 2개 이상으로 늘어날 때
익절: 우리 TP의 90% 도달 시 절반
손절: −20%
갱신 리스크: Q5가 주력인 종목은 컨센 갱신 즉시 재평가
```
애널리스트는 목표가만 내면 되지만 **PB는 언제 뺄지를 답해야 한다.**

**④ 고객 유형**
```
공격형: 정렬 상위 3개 그대로
안정형: 하드컷 통과 종목 중 유동성·승률 상위 3개
```

**"유망합니다"로 끝내지 마라. 반드시 금액으로 끝낸다.**

```
/desk-head                            → runs/<run_id>/report.html
```

산업명을 안 주면 `industry-screen` 이 되묻는다 — **데스크가 산업을 대신 고르지 않는다.**

### 도구 단독 실행

스킬 없이 데이터만 뽑을 수도 있다.

```bash
python tools/env_keys.py check                       # 키 확인
python tools/industry_cache.py list-industries       # 등재된 산업
python tools/fetch_consensus.py 062040 103590        # 컨센서스 수집 (병합)
python tools/fetch_roic.py 062040 --json             # ROE·ROIC
python -m unittest discover -s tests -t .            # 테스트
```

### 재현성 테스트

같은 입력으로 3회 돌려 판정이 흔들리는지 본다.

```
/pro_tackler runs/<run_id>/ 를 3회 실행하고 심사표를 비교
```

흔들리면 해당 관문의 문구가 모호한 것이므로 SKILL.md를 고친다.

## 11. 하지 않을 것

명시적으로 버린다. 하나의 기준으로 불려나가기 위해서.

`초단타·수급·차트 신호` `산업 3개 동시 완주` `FnGuide 크롤러` `웹 UI·대시보드`
`컨센서스 없는 종목` `비상장·Pre-IPO` `DCF·IRR 모델` `21점 채점표` `앵커 바스켓 멀티플`

**DCF를 버리는 이유**: 컨센서스가 멀티플로 만들어지는데 우리가 DCF로 답하면
**델타의 출처가 가정 차이인지 방법론 차이인지 구분되지 않는다.**
같은 자로 재야 차이가 근거가 된다.
